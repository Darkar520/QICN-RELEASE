## Unified Trace Architecture

The raw OFIA trace is one unified trace generated by the same synthetic oracle and shared by seed. It contains two observable signal families:

1. `self_locus_trace`: the same family consumed by `extractSelfLocus`.
2. `perturbation_events`: directed perturbations with downstream response observations.

The key field is:

`perturbation_target_id`

This is observable by design because an experimenter knows which candidate locus received the perturbation. It is not the latent truth of which locus is self.

The extractor never receives:

- `true_self_locus_id`;
- `latent_truth`;
- `is_self_target`;
- `expected_ownership`;
- `control_ownership`;
- cooked ownership scores;
- precomputed `QICN_OFIA`.

## Extractor Mechanism

Artifact:

`docs/ai-platform-outputs/sims/qicn_phase6_3e_ofia_extractor.js`

Mechanism:

1. Run `extractSelfLocus` on `raw_trace.self_locus_trace`.
2. Treat the returned `selected_locus_id` as the inferred self-locus.
3. Classify each perturbation event as inferred self-target if:

   `event.perturbation_target_id == inferred_self_locus_id`

4. Compute downstream response magnitude from raw pre/post channel values, response delay, recovery fraction, and perturbation amplitude.
5. Compute paired self-target minus non-self-target response differences within each `pair_id`.
6. Convert the paired standardized effect into `QICN_OFIA`.

This is an architectural dependency on SelfIndex, not a circularity. OFIA does not independently know the self-locus.

## Error Coupling

Because OFIA uses the inferred self-locus, SelfIndex errors propagate directly into OFIA labels.

This is a structural limitation of the gate. `SIPM` and `OFIA` are not independent votes. In later implementations, `CFS` may also share upstream self anchoring or trajectory segmentation choices, so the nominal count of raw variables can overstate effective independence.

Phase 6.3E measures the direct `SelfIndex -> OFIA` error propagation instead of hiding it.
