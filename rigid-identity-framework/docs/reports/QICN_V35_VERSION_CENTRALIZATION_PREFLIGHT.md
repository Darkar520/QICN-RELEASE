## Executive Finding

The attached v35 centralization prompt identifies a real maintenance problem: the repository has accumulated multiple versioned adjudicators, calibrators, auditors, signature verifiers, fixtures, reports, and npm entrypoints. However, the prompt's implementation instructions are not safe to execute literally against the current working tree.

The current checkout is materially different from the prompt assumptions:

- Detected versioned scripts: **16**, not 17.
- Detected `package.json` script keys: **66**, not 74.
- Detected version-specific script keys: **21**.
- Detected versioned fixture-like files under `docs/fixtures`: **9**, not only 3.
- Detected versioned report-like files under `docs/reports`: **44**, not only 9.
- Several v28/v30/v31 scripts and reports are currently untracked, while several v27/v25 files are modified. A physical move would entangle unrelated prior work.

## Dependency Hazards Confirmed

The prompt correctly identifies several imports that would break if files were moved without a compatibility layer:

- `scripts/external-session-zero-adjudicator-v31.js` imports from `./external-session-zero-adjudicator-v30`.
- `scripts/negative-control-suite.js` imports from both `./external-session-zero-adjudicator-v30` and `./external-session-zero-adjudicator-v31`.
- `scripts/ar1-correction-clinical-summary-v28.js` imports from `./external-session-zero-adjudicator-v28`.
- `scripts/calibrate-session-zero-thresholds-v27.js` imports from `./external-session-zero-adjudicator-v27`.
- `scripts/audit-v27-superior-gaps.js` imports from `./external-session-zero-adjudicator-v27`.
- `scripts/validate-promotion-rules.js` imports from `./audit-operational-term-promotions-v28`.

Because these imports are active, a simple `Move-Item scripts/*-vNN.js scripts/legacy/` would break runnable verification unless every moved file is replaced immediately by a wrapper or every importer is patched atomically.

## Working Tree Risk

The working tree is not pristine. It contains modified tracked files and numerous untracked v28/v30/v31 artifacts generated by previous hardening passes. In this state, physically moving reports, fixtures, and scripts would make it difficult to distinguish:

- v35 centralization edits,
- v33 mathematical hardening artifacts,
- v27/v28 generated report refreshes,
- unrelated user changes,
- untracked recovery artifacts.

This is exactly the kind of condition where a hard cleanup pass can accidentally erase or obscure provenance.

## Decision

Do **not** execute the literal v35 prompt in the current dirty tree.

The correct next implementation should be a two-stage centralization:

1. **Stage A: Non-destructive central command layer**
   - Add current canonical npm aliases (`verify`, `calibrate`, `adjudicate`, `audit:terms`, `audit:veto`, `audit:gaps`) without removing legacy scripts.
   - Add `VERSION.md` documenting v34/v35 mapping and deprecation policy.
   - Add `scripts/legacy/README.md` describing the intended wrapper architecture.
   - Add `scripts/legacy/run-all-legacy-verifications.js` that calls existing root scripts first, proving baseline compatibility.

2. **Stage B: Physical archive and wrapper conversion**
   - Execute only after the tree is clean or after a deliberate checkpoint commit/stash.
   - Copy versioned files to `scripts/legacy/originals/` first.
   - Replace root versioned scripts with thin wrappers or update package/imports atomically.
   - Move reports/fixtures only after manifesting hashes and destination paths.
   - Run `npm run verify:v25`, `verify:v26`, `verify:v27`, `verify:v30`, `verify:v31`, `node scripts/negative-control-suite.js`, and `node scripts/validate-promotion-rules.js` before and after.

## Safe v35 Implementation Plan

### Phase 0: Baseline Freeze

- Record `git status --short`.
- Record hashes for every versioned script, fixture, and report to `docs/reports/V35_VERSIONED_ARTIFACT_MANIFEST.json`.
- Run current gates: `npm run verify:v25`, `verify:v26`, `verify:v27`, `verify:v30`, `verify:v31`.

### Phase 1: Canonical Entry Points

- Add clean aliases to `package.json` while preserving legacy keys:
  - `verify` -> current strict chain (`verify:v31`)
  - `calibrate` -> current calibrator (`calibrate:session-zero-thresholds:v27`)
  - `adjudicate` -> current adjudicator (`adjudicate:external-session-zero-v31`)
  - `audit:terms` -> current strongest auditor (`audit:operational-term-promotions:v27` or v28 after verifying target scope)
  - `audit:veto` -> current strongest veto verifier (`verify:human-veto-signature:v27` or v28 after verifying registry behavior)
  - `test:negative-controls` -> existing negative-control suite
- Do not remove `verify:v25` through `verify:v31` yet.

### Phase 2: Wrapper Architecture

- Create `scripts/legacy/README.md`.
- Create `scripts/legacy/run-all-legacy-verifications.js`.
- Create wrapper prototypes for one low-risk path first (`external-session-zero-adjudicator-v31`) and verify exact verdict parity.
- Only then generalize wrappers.

### Phase 3: Physical Move

- Move versioned scripts only after wrappers are passing.
- Move old reports and fixtures only after a hash manifest exists.
- Keep `docs/fixtures/EXTERNAL_SESSION_ZERO_SYNTHETIC_FIXTURE_v27.json` in place as the canonical current fixture.

### Phase 4: Final Cleanup

- Reduce `package.json` only after all documented legacy commands have replacement commands.
- Generate `VERSION.md`.
- Generate final `QICN_V35_VERSION_CENTRALIZATION_REPORT.md`.
